# Autoencoder for scRNA data:
For your autoencoder use case
Preprocessed data is actually fine — even preferred in many cases — because:

Autoencoders work with normalized/log-transformed data better than raw counts. Log transformation stabilizes variance and makes the distribution more normal, which helps gradient-based learning.
Your goal is gene perturbation representations, not absolute counts. You need meaningful embeddings of cell states, not raw UMI counts.
If batch correction was applied, that's good — it removes technical noise.

bottleneck size: 
- not 2, because we have approx. 3k genes and it will compress TOO much
- typical scRNA latent dims: 10-50 (look up paper -> see Mohamad Kassab et al., 2026)
    so try with 16-128 depending on complexity
    -> used 32 as bottleneck in autoencoder.py

    However, Mohamad Kassab et al., 2026, which systematically benchmarked 
    VAE-based methods (scVI, MrVI, LDVAE) across four datasets with 120 
    different configurations, found that “moderate-to-high latent dimensionality (>30) 
    often gives the best balance” between batch correction and biological conservation. 
    Sensitivity to latent size was dataset-dependent, with larger latents improving 
    batch mixing but sometimes reducing biological conservation.

- avoid dead neurons so use ELU or LeakyReLU

# AE loss in autoencoder.py described by ChatGPT-5 mini:
Your loss magnitudes are large because your negative-binomial loss is a summed 
negative log-likelihood across genes (features) and then averaged over batch rows, 
so values scale with number of genes per cell. Points and quick checks/fixes:

What your loss computes
negative_binomial_log_prob returns per-element log-probabilities (shape: [batch, genes]).
negative_binomial_loss does -(log_prob.sum(dim=1)).mean() → you sum over genes, 
then average over cells. So loss ≈ average negative log-likelihood per cell (not per gene). 
For cdims ≈ 3k, per-cell NLL of ~900–1000 is plausible.

Make the number interpretable
Per-element (per gene) NLL: loss_per_gene = loss_value / cdims
Per-count average: loss_per_count = loss_value / (cdims * batch_size) if you want 
per-element across whole batch.
Example: for cdims=3000 and reported loss ≈ 900 → per-gene ≈ 0.3 nats (or 0.43 in bits).

Verify sign/scale and baselines
Compute NLL for trivial baselines to ensure model improves:
mu = counts (saturated) → should give very small/zero NLL per cell when using mu_sat 
in your deviance code.
mu = counts.mean(dim=0).unsqueeze(0) (gene-wise mean) → baseline loss to compare.
If your model's loss decreases over epochs, training is working regardless of large 
absolute numbers.

Numerical/parameter checks that can inflate loss
Dispersion magnitude: huge/small theta can change likelihood scale. Inspect 
model.get_dispersion().mean()/min/max.
Decoder outputs: you apply Softplus, so mu>=0; good. Ensure mu scale matches 
counts (no unintended scaling).
Epsilon/clamping: you clamp mu and theta; ensure eps isn't too large.
Data: confirm adata.X contains raw counts (integers) and not already 
log-transformed or normalized.

Suggested diagnostics (run a few quickly)
Print shapes and a few stats during evaluation: print(batch.X.shape, 
reconstructed.shape, dispersion.shape) print('loss_batch_sum, loss_per_gene, 
loss_per_cell:', loss.item(), loss.item()/cdims, loss.item()/batch_size)
Baseline losses: mu_mean = full_counts.mean(dim=0, keepdim=True) 
baseline_loss = negative_binomial_loss(full_counts, mu_mean.expand_as(full_counts), dispersion)
Check dispersion: d = model.get_dispersion(); print(d.min().item(), d.mean().item(), d.max().item())
If you want per-gene reported loss in your pipeline, change negative_binomial_loss 
to return per-element mean:
return -(log_prob).mean()

Summary: 900–1000 is not inherently bad — it's the average negative log-likelihood 
per cell summed over ~3k genes. Convert to per-gene or compare against baselines and 
training trends to judge performance.


Why sum_genes_mean_batch wins for scRNA-seq
Gene expression is highly skewed — a few genes (ribosomal, housekeeping) have counts in thousands; most are sparse with 0–10 counts. Global mean would let high-count genes overwhelm the loss signal.
Cell-level modeling makes sense — you want the model to reconstruct each cell's expression profile well, not optimize for the largest numbers. Summing per-cell naturally treats each cell as an independent unit.
Matches biological intuition — a cell is the unit of observation; all ~5k genes are attributes of that cell. Averaging across cells respects this hierarchy.
Standard in the literature — scVI, NBVAE, and other tools use the per-cell-sum approach for exactly this reason.
